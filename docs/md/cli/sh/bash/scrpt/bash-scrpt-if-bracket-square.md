
# `[ ]` と `[[ ]]` の違い


## `[ ]` (test コマンド)

- POSIX 準拠の外部コマンド ( `/usr/bin/[` ) またはシェル組み込み
- 移植性が高い (sh, dash など他のシェルでも動く)
- 変数展開時に word splitting やグロブ展開が起きるため, 変数はダブルクォートで囲む必要がある

```bash
# クォートしないとスペース入りの値で壊れる
if [ "$var" = "hello" ]; then ...
```


## `[[ ]]` (bash/zsh キーワード)

- bash 2.02 以降で使えるシェルの予約語 (キーワード)
- シェルが構文として解析するため, 内部で word splitting やグロブ展開が起きない
- 追加機能が使える:
  - `=~` で正規表現マッチ
  - `&&`, `||` を条件式の中に直接書ける
  - パターンマッチ ( `==` の右辺がグロブとして解釈される)

```bash
# クォートなしでも安全
if [[ $var == hello* ]]; then ...

# 正規表現
if [[ $line =~ ^[0-9]+$ ]]; then ...

# 論理演算子を内部に書ける
if [[ -f $file && -r $file ]]; then ...
```


## 主な差異まとめ

| 観点           | `[ ]`                | `[[ ]]`                    |
|----------------|----------------------|----------------------------|
| 種別           | コマンド (builtin)   | シェルキーワード           |
| POSIX 準拠     | はい                 | いいえ (bash/zsh/ksh 拡張) |
| word splitting | 起きる               | 起きない                   |
| 正規表現 `=~`  | 使えない             | 使える                     |
| パターンマッチ | 使えない             | `==` 右辺がグロブ          |
| 論理演算子     | `-a` / `-o` (非推奨) | `&&` / `||`                |
| 変数クォート   | 必須                 | なくても安全               |


## 使い分けの指針

- bash 専用スクリプトなら `[[ ]]` を使う方が安全で読みやすい
- `/bin/sh` や POSIX シェルとの互換性が必要なら `[ ]` を使う
